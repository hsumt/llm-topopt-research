# Baseline experiment: ATO cascade on a stress-constrained L-bracket

Branch `experiment/L_bracket_ATO`. Run 2026-09-01, low-fidelity tier (1024 elements).
Reference: Holmberg E., Torstenfelt B., Klarbring A. (2013), "Stress constrained topology
optimization", *Struct Multidisc Optim* 48:33–47.

All verdicts in this document come from re-solving the modified problem. None is hardcoded,
and no expected outcome was written into the code. Candidate edits were generated by a
language model at run time.

---

## 1. What was built

**Benchmark** (`project/topopt/stress/`) — Holmberg's formulation, not compliance with a
stress plot added afterward: bilinear Q4 elements with one stress evaluation point at the
centroid, cone design-variable filter, SIMP stiffness penalization `q = 3`, stress
penalization `eta_S = rho^(1/2)`, clustered modified P-norm stress measure normalized by the
limit, stress-level clustering with reclustering every iteration, adjoint sensitivities, and
formulations P1 (min mass s.t. stress), P2 (min compliance s.t. stress and mass) and P3 (min
compliance s.t. mass). Depends on numpy and scipy only.

**Cascade** (`project/ato/`) — convergence gate, deterministic anomaly predicates,
model-generated candidate edits constrained to an explicit grammar, deductive discharge by
re-solving every candidate and every subset, then ranking behind an authority gate.

### Verification performed

| Check | Result |
|---|---|
| Element count at the paper's h = 2 mm | **6400**, matching the paper's stated discretisation exactly |
| Adjoint vs. central finite differences, directional, P1 / P2 / P3 | max relative error **1.5e-10 / 9.6e-8 / 9.6e-8** at h = 1e-4 |
| Error behaviour under step refinement | error *grows* as the step shrinks — round-off on the finite-difference side, the signature of a correct analytic gradient |
| Hash-bound verification manifest | **intact**; 27 hashed files listed, none modified |

The Q4 element stiffness and the vendored Svanberg MMA are imported from the repository's
existing verified modules rather than re-implemented, so the new solver and the pre-existing
verification suite share one definition of each.

## 2. Benchmark result — the paper's comparison reproduced

Low-fidelity tier, 1024 elements, all three formulations at the mass fraction found optimal
by P1 (0.4037), which is how the paper sets up its own comparison.

All three are given the same 400-iteration budget so the comparison is not confounded by
termination point; each row reports where it actually stopped.

| | iterations | terminated | compliance (N mm) | peak von Mises (MPa) |
|---|---|---|---|---|
| P1 min mass s.t. stress | 400 | budget reached, stress-feasible | 5069 | 457 |
| P2 min compliance s.t. stress + mass | 349 | converged and feasible | 4056 | 457 |
| P3 min compliance s.t. mass | 122 | converged and feasible | 4030 | 504 |

P3 places material directly at the re-entrant corner, which is the paper's headline
observation. **Do not read the rest of this table as agreement with the paper** — see §2a,
which measures that directly and finds it does not hold. **P1 is reported as
stress-feasible but not converged**: its worst normalized cluster constraint reached +0.0021,
inside the declared feasibility tolerance, while the design change had not fallen below
tolerance at 400 iterations. Reclustering every iteration keeps the constraint set moving, so
the objective oscillates slightly; the paper reports the same behaviour.

**Reference-tier cost probe** (Holmberg's own h = 2 mm mesh, 6400 elements, 13202 dof):
**0.093–0.094 s per iteration for P3 and 0.13–0.16 s for P1** on this machine, across two
runs. These are single-sample wall-clock timings of one evaluation, not benchmarked means, so
they are quoted as a range and should be re-measured on the machine that will do the work. The
cascade itself is not run at this tier, because it re-solves the problem once per candidate
and once per subset.

## 2a. Quantitative comparison against the paper — it does NOT reproduce

Run at the paper's own discretisation (6400 elements, h = 2 mm), each case configured to match
a specific published table. `project/experiments/lbracket/run_paper_comparison.py`, record in
`artifacts/benchmark/paper_comparison_reference.json`.

| case | published | this implementation | ratio |
|---|---|---|---|
| Table 1, P1, stress-level, recluster every iteration | M = 24.76 g, C = 10,330 | M = 55.33 g, C = 2,569, **did not converge, stress-infeasible**, peak 957 MPa | mass 2.24×, C 0.25× |
| Table 2, P1, distributed-stress, every iteration | M = 20.63 g, C = 13,277 | M = 55.20 g, C = 3,808, **did not converge, stress-infeasible**, peak 939 MPa | mass 2.68×, C 0.29× |
| Table 5, P3 at the Table-2 mass | M = 20.63 g, C = 10,960 | M = 20.63 g (exact), C = 5,003, converged in 241 | mass 1.00×, **C 0.46×** |
| Table 5, P2 at the Table-2 mass | M = 20.63 g, C = 14,347 | M = 26.39 g (limit violated), C = 7,805, did not converge | mass 1.28×, C 0.54× |

**Formulation ordering does not match.** Published: P3 (10,960) < P1 (13,276) < P2 (14,347) —
P2 is the *most* compliant. Measured here: P1 (3,808) < P3 (5,003) < P2 (7,805). An earlier
draft of this document claimed the ordering matched; that claim was wrong and is withdrawn.

**What does match, exactly.** Every input was checked against the paper: L = 200 mm,
thickness 1 mm, 6400 four-node elements with one centroid stress point, E = 71,000 MPa,
ν = 0.33, ρ = 2.8e-9 ton/mm³, yield and stress limit 350 MPa, ten clusters, a 1500 N point
load, 3 × 2 elements under the load outside the design space, r0 = 1.5 × element size, and the
compliance objective **C = ½ Fᵀu** — the paper states that definition explicitly, so the gap is
not a factor-of-two convention error. The fully solid L-beam gives **71.68 g**, matching the
paper's implied full mass exactly, with a 2.65 mm tip deflection and C = 1,984 N mm, about 2×
a single-cantilever estimate as the L's two-segment load path requires. The mesh, material,
assembly and mass scale are therefore sound.

**Two unreconciled discrepancies.**

1. *P3 is too stiff by ~2.2× at identical mass and mesh.* At exactly 20.63 g my converged P3
   sits at 2.52× the solid-body compliance where the paper's sits at 5.52×. Same problem, same
   discretisation, same objective definition, and mine finds a markedly stiffer design. This is
   **not explained**. Candidates not yet tested: the density continuation schedule, MMA move
   limits and asymptote parameters (the paper does not publish these), and the possibility that
   one of the two solutions is a different local optimum. Testing them is the next step; **not
   assessed**.
2. *P1 does not converge at the paper's mesh.* At 1024 elements P1 reaches 28.94 g and is
   stress-feasible. At 6400 elements, over 400 iterations, mass instead climbs to ~55 g and the
   design remains stress-infeasible with peak stress near 950 MPa. Each cluster then holds 640
   stress points instead of 102, and the P-norm's underestimate of the maximum grows with the
   number of points in the cluster, so local control weakens sharply — the paper discusses this
   dependence on `nc` but uses ten clusters at this mesh successfully. **The stress-constrained
   formulation in this implementation does not currently scale from the low tier to the paper's
   discretisation.** The cascade results in §4 are unaffected, since they run entirely at the
   low tier, but the reference tier cannot be used as a validated benchmark until this is fixed.

**Consequence for the cascade results.** §4 is a self-consistent experiment on this
implementation at the low tier: the baseline converges, the predicates fire on measured
quantities, and every verdict comes from a re-solve of the same solver. None of that depends on
matching the paper's published numbers. What it does mean is that **this is not yet a validated
reproduction of Holmberg et al.**, and the mechanism-level agreement (P3 puts material in the
corner; stress constraints move it out) should be quoted as qualitative, not quantitative.

## 3. The anomaly predicate — a result in its own right

The first cascade run used the obvious predicate, peak von Mises above the stated allowable.
Every physically motivated candidate was eliminated and the sole survivor was
`relax_stress_limit(610 MPa)`, an intent-altering edit, so the authority gate refused and the
run terminated in a flagged diagnosis. Preserved as
`artifacts/ato/ato_cascade_low_P3_peak_predicate.json`.

That outcome is an artefact of the stress measure, not of the structure. The paper proves the
clustered P-norm *underestimates* the maximum local stress, and states that stresses will
locally exceed the limit in any attainable design. A peak predicate therefore fires on
everything, and only raising the allowable can entail it away.

Measurement identified the discriminating quantity as the **extent** of overstress:

| | solid elements above 350 MPa | peak / p95 |
|---|---|---|
| P3, the stated problem | 183 / 315 = **58%** | 1.12 — general overstress |
| P1, stress-constrained | 17 / 436 = **3.9%** | 1.33 — isolated local peaks |

`OVERSTRESS_FRACTION_LIMIT = 0.10` is a declared calibration decision taken from the paper's
own criterion that a good design leaves only a small number of points above the limit. Any
threshold between roughly 0.05 and 0.55 produces the same partition, so the verdict is
insensitive across an order of magnitude. It was not tuned to make any candidate survive.

A three-configuration ablation — the same stated problem, the same generated candidate set,
the same cached re-solves, varying only which predicates are targeted — is in
`artifacts/ato/predicate_ablation_low.json`.

## 4. Cascade result — a coupled defect across three slots

Baseline: P3, converged and feasible in 67 iterations at the stated mass fraction of 0.30.
Three predicates fired.

| anomaly | evidence at baseline |
|---|---|
| `widespread_overstress` | 183 of 315 solid elements (58.1%) above 350 MPa; peak 605.6, p95 542.9, median 363.3 MPa |
| `reentrant_corner_overstress` | 7 of 21 solid elements within 15 mm of the corner above the allowable |
| `load_point_overstress` | 2 of 8 solid elements within 15 mm of the load point above the allowable |

**Round 1** — 5 model-generated candidates, 25 discharges, outcome `no_survivor`
(0 survived, 14 eliminated, 6 infeasible, 5 not assessed). All 11 of the failures involving
`add_stress_constraints(P2)` split **6 INFEASIBLE and 5 NOT_ASSESSED** — the singleton itself
is NOT_ASSESSED, its worst constraint still descending (+0.2535 → +0.2409 over the last 50
iterations) at the discharge budget. **A NOT_ASSESSED discharge is an absence of evidence, not
an infeasibility verdict**, so P2-at-0.30 was not proven infeasible by the discharge stage
alone; the candidate the model later proposed in round 2 records exactly that reading.

What P2 inherits is the stated 0.30 mass limit, and that was tested separately rather than
inferred: at mass ≤ 0.30 the worst constraint plateaus flat at +0.21 over the last 20 of 400
iterations, while at mass ≤ 0.40 the same problem converges feasibly. **On that independent
check, the stated mass budget and the material's own yield limit are jointly unsatisfiable.**

**Round 2** — the generator, given the round-1 verdicts including the infeasibility reasons,
proposed `increase_mass_budget(0.45)` and a larger 20 mm corner fillet. 129 discharges:
9 survived, 63 eliminated, 34 infeasible, 23 not assessed.

Across that full enumeration, the 66 discharges containing an `add_stress_constraints` edit
break down as **34 INFEASIBLE, 23 NOT_ASSESSED, 7 ELIMINATED, 2 SURVIVES**. Both survivors also
contain `relax_stress_limit`, so neither is evidence that adding stress constraints repairs the
specification at the stated mass budget.

Minimal edit sets clearing each anomaly:

| anomaly | minimal clearing edit | tier |
|---|---|---|
| `widespread_overstress` | `increase_mass_budget(0.45)` | T3 |
| `reentrant_corner_overstress` | `declare_corner_fillet(20 mm)` | T2 |
| `load_point_overstress` | only `relax_stress_limit` was found | T3 |

Each anomaly is cleared by an edit in a **different slot** of the problem statement. The only
single edit clearing all three is `relax_stress_limit(606 MPa)` — T3, UNBOUND.

**Outcome: `flagged_intent_altering`.** Every minimal survivor is intent-altering or carries
parameters the stated problem does not determine, so the mechanism reports and applies
nothing. That is the correct terminal state: an edit that changes what the engineer asked for
requires human authority.

**Non-monotone re-entry was observed in 8 subsets.** `refine_stress_clusters` and
`increase_mass_budget` were each eliminated alone and re-entered in surviving subsets. This is
the empirical justification for enumerating the subset layer rather than screening singletons.

## 5. Two findings that bear on the framework's design

**The grammar must own tier assignment, not the model.** Of the five candidates for which the
model volunteered an admissibility tier, one agreed with the grammar. Both
`relax_stress_limit` and `increase_mass_budget` were proposed as **T1 intent-preserving**;
the grammar classifies both as **T3 intent-altering**. Had tier assignment been delegated,
the authority gate would have been bypassed and an edit that changes the engineer's stated
requirements applied silently. The proposal's decision to fix tiers in the grammar is
load-bearing, and this run is direct evidence for it.

**The cascade rediscovered a caveat the paper states in prose.** The paper notes that a
feasible design may be hard to find with P2 at a low allowable mass, and that a slightly
higher mass yields a feasible solution with lower compliance. The cascade reached the same
conclusion from re-solves alone: no P2-at-0.30 subset yielded a repair — 6 INFEASIBLE and
5 NOT_ASSESSED in round 1 — and given those reasons the generator proposed raising the mass
budget, which then cleared the widespread-overstress anomaly. It was not given the paper.

## 6. Known limitations of this baseline

- **The corner-relief mechanism is partly suppressed at this fidelity.** P1 clears widespread
  overstress but still fires both feature predicates, because `r0 = 1.5h = 7.5 mm` here
  against 3 mm at the reference tier — the filter is 2.5× coarser relative to the domain, so
  fine corner relief cannot form. A corner-locality predicate consequently loses discriminating
  power at the low tier while the extent predicate retains it. Repeating the cascade at the
  `medium` tier would test this directly; **not assessed**.
- **`distribute_load` should be treated with suspicion as a repair.** It clears
  `load_point_overstress`, but the paper warns that distributing the load produces a design
  that is more optimal with respect to the formulated problem yet physically useless, since a
  small load-direction perturbation would collapse it. The grammar has no predicate that would
  catch this, so the mechanism cannot currently distinguish a genuine repair from a spurious
  one here.
- **23 of 129 discharges are `NOT_ASSESSED`**, mostly stress-formulation re-solves still
  descending at the 200-iteration discharge budget. They carry no verdict and are not counted
  as eliminations.
- **The generated candidate set varies between runs.** The predicate ablation controls for
  this by generating once and reusing; a comparison across separate cascade invocations does
  not.
- **The proposal's own flagship defect class is not exercised here, and cannot be.** The ATO
  worked example's L-bracket defect is an **omitted out-of-plane (transverse) load case** — the
  specification names one in-plane load, the solver returns a correct optimum for it, and the
  design is fragile under a load nobody stated. That defect is structurally unavailable in this
  benchmark: Holmberg's formulation is 2-D plane stress (the paper says so, and this
  implementation follows it), so each node carries only `u, v` and an out-of-plane load has no
  degree of freedom to act on. It does not answer weakly — **it cannot be asked**. What §4
  exercised is a *different* defect class: jointly unsatisfiable stated requirements (mass
  budget against yield) plus a geometric feature (the re-entrant corner). Both are legitimate
  specification defects, and the coupled-subset and authority-gate machinery is the same, but
  **no conclusion here transfers to the omitted-load-case defect**, which is the one the
  proposal's worked example turns on. Reaching it requires a formulation change, not another
  load case: Mindlin–Reissner shell, 2.5D extrusion with density constant through the
  thickness, or full 3D. If the in-plane *direction* of the tip load is what is meant instead,
  that is an ordinary extra load case at roughly 2× solve cost with no remesh, and is
  available today.
- **Single load case, no buckling, stiffness or eigenfrequency constraint.** This matters for
  the `distribute_load` caution above: the paper's objection to load distribution is a
  stability argument, and nothing in this model can express stability.

## 7. Reproducing

```bash
python -m project.topopt.stress.verify_gradients
python -m project.experiments.lbracket.run_benchmark --fidelity low
python -m project.experiments.lbracket.run_ato --fidelity low --max-subset-size 3
python -m project.experiments.lbracket.run_predicate_ablation --fidelity low
```

The cascade constructs its Anthropic client from `ANTHROPIC_API_KEY` in the process
environment. `dotenv.load_dotenv()` is the mechanism that puts it there, so the repository's
own runtime does load `.env` into the environment — that is the standing convention in this
repo and matches `project/llm/critic.py`. What was held to throughout this work is narrower
and is the rule that was asked for: **no agent, tool, or analysis step in this session opened,
read, printed, parsed, or listed the contents of `.env`**, and no credential value appears in
any source file, artifact, log, or commit produced here. The key is read by the SDK from the
process environment at call time and never inspected.

### Which model access produced these results

**No call in this work was billed to `ANTHROPIC_API_KEY`.** That variable was not present in
the environment the cascade ran in, so the runs were driven through an injected
`CallableBackend` wired to platform-supplied model access. Every candidate edit was still
generated live by a model at run time — `claude-sonnet-5`, recorded as `generation.model` in
both `ato_cascade_low_P3_multiround.json` and `predicate_ablation_low.json`. Total across the
session: **10 calls, 25624 input tokens, 6871 output tokens.**

**`AnthropicBackend` is therefore an unverified code path.** It is the backend `run_ato.py`
constructs by default, and it is the one that will consume your credits, but no live call has
gone through it: the run environment had neither the key nor the `anthropic` package, so
construction fails at the import guard. Before a real cascade run, validate it with one
minimal call:

```bash
pip install anthropic python-dotenv          # if not already present
python -m project.experiments.lbracket.run_ato --check-backend
```

That makes a single tool-use round trip costing a few hundred tokens and prints the resolved
model and usage. Only the guard path (`BackendError` on a missing package or key) has been
exercised here; the success path has not.
